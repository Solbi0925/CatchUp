# CatchUp 프로토타입 UX 보완 설계

## 목적

최종 목 기반 프로토타입에서 발견된 온보딩 정렬 문제와 Today·Month·AI Mate 상호작용 누락을 보완한다. 사용자는 현재 보고 있는 화면에서 일정을 수정하고, Today의 맥락을 유지한 채 AI Mate 입력창으로 자연스럽게 이동할 수 있어야 한다.

## 범위

- Google Calendar 온보딩 아이콘 정렬과 연결선 표현 보정
- Today의 계획 생성 진입, 할 일 맥락형 Prompt Chips, 빈 날짜 계획 조정 진입
- Today와 Month에서 모든 일정 직접 수정
- AI Mate 메시지 시간 제거와 입력 전용 Prompt Chips
- Today 상단 안전 여백과 브리핑 문장 줄바꿈 보정
- 일정 추가 버튼 문구 단축

`DATA_MODEL.md`와 `API_SPEC.md`는 이번 변경 범위에서 제외한다. 주간 계획 생성 주 1회 제한과 AI Mate 계획 조정 하루 10회 제한은 유지한다.

## 1. Google Calendar 온보딩

- Google Calendar 아이콘 바깥 프레임은 회색 대신 연보라색 테두리와 옅은 연보라색 배경을 사용한다.
- 제공된 파란색 Google Calendar 이미지는 프레임의 수평·수직 정중앙에 배치한다.
- Google Calendar와 CatchUp 아이콘 사이의 보라색 점선은 두 프레임 사이의 빈 공간에만 보인다.
- 점선이 어느 아이콘의 이미지나 테두리 위에도 겹치지 않도록 아이콘 프레임이 연결선보다 위 레이어에 놓인다.

## 2. Today 화면

### 상단과 브리핑

- 모바일 상태바를 고려해 화면 최상단과 주간 날짜 선택기 사이에 안전 여백을 추가한다.
- `4주 일정을 고려해 중요한 일부터 정리했어요.`는 일반 모바일 너비에서 한 줄로 표시한다.
- 하위 문구와 캐릭터 위치는 기존 카드 구조를 유지하되 본문이 캐릭터 영역을 침범하지 않는다.

### 계획 미생성 상태

- 업로드 자료 확인까지 끝났지만 주간 계획이 없으면 `계획 생성하기` 버튼을 표시한다.
- 버튼을 누르면 AI Mate 패널을 열고 입력창에 `이번 주 계획을 생성해줘`를 채운다.
- 이 동작은 메시지를 전송하지 않는다. 사용자가 요구사항을 덧붙인 뒤 직접 보내기 버튼을 눌러야 한다.

### 할 일이 있는 날짜

- 완료 체크박스는 기존처럼 완료 상태만 변경한다.
- 체크박스를 제외한 할 일 카드 본문을 누르면 AI Mate 패널을 연다.
- 패널의 입력창 위에 다음 Prompt Chips를 표시한다.
  - `할 일 추천이유`
  - `할 일 조정`
  - `{M/D}일 할 일 추가`
- 각 칩을 누르면 아래 문장을 입력창에 채우되 전송하지 않는다.
  - `{할 일 제목}을 추천한 이유를 알려줘`
  - `{할 일 제목} 할 일을 조정해줘`
  - `{M/D}일 할 일을 추가해줘`
- 새 진입 맥락이 생기면 기존 칩 목록을 교체하고, AI Mate 패널을 닫으면 맥락형 칩을 초기화한다.

### 할 일이 없는 날짜

- 빈 상태 설명 아래에 `계획 조정` 버튼을 표시한다.
- 버튼을 누르면 AI Mate 패널을 열고 `{M/D}일 계획을 조정해줘`를 입력창에 채운다.
- 이 동작도 메시지를 자동 전송하지 않는다.

### 일정 섹션

- `일정 추가` 버튼 문구를 `추가`로 변경한다.
- Google Calendar, CatchUp 직접 입력, Upload 추출 일정 모두 일정 카드를 눌러 현재 화면의 편집 창에서 수정할 수 있다.

## 3. Month 화면 일정 수정

- 날짜 상세의 `일정 추가` 버튼 문구를 `추가`로 변경한다.
- Upload 추출 일정도 읽기 전용 상세가 아니라 동일한 일정 편집 폼을 사용한다.
- 제목, 날짜, 시작 시간, 종료 시간과 6색 팔레트의 카테고리 색상을 수정할 수 있다.
- 같은 과목의 색상을 바꾸면 기존 정책대로 같은 과목의 모든 일정에 적용한다.

## 4. 일정 데이터 반영

- CatchUp 직접 입력 일정은 기존 `calendar/eventUpdated` 흐름을 사용한다.
- Google Calendar 목 데이터는 프로토타입 세션의 이벤트 오버라이드로 갱신한다.
- Upload 추출 일정은 새로운 `extraction/itemUpdated` 상태 변경으로 원본 `ExtractedItem`을 갱신한다.
- Today와 Month는 동일한 상태를 읽으므로 한 화면에서 저장한 Upload 일정 변경이 다른 화면에도 즉시 반영된다.
- 학업 일정의 유형과 문서 연결 정보는 유지하며, 편집 가능한 필드는 제목·날짜·시간으로 제한한다. 종료 시간이 없는 추출 일정은 종료 시간을 비워둘 수 있다.

## 5. AI Mate 패널

- AI Mate와 사용자 메시지 말풍선 아래의 시간 표시는 모두 제거한다.
- Prompt Chips는 대화 로그와 입력창 사이에 배치한다.
- 칩은 현재 Today 진입 맥락에서만 표시한다.
- 칩을 눌러도 대화 로그에 사용자 메시지가 추가되지 않고 응답 로딩도 시작되지 않는다.
- 사용자가 입력창의 보내기 버튼을 누르거나 Enter를 눌렀을 때만 기존 메시지 전송 흐름을 실행한다.
- 기존 자기소개, 계획 생성 안내, 주 1회 생성 제한과 하루 10회 조정 제한은 그대로 유지한다.

## 6. 컴포넌트 및 상태 경계

- `AiMateProvider`
  - `openWithDraft(draft, chips?)`로 패널, 입력 초안, 선택 Prompt Chips를 함께 관리한다.
  - 칩 선택은 `setDraft`만 실행한다.
- `AiMateLayer`
  - 메시지 시간을 렌더링하지 않는다.
  - 활성 Prompt Chips를 입력창 위에 렌더링한다.
- `TodayPage`
  - 선택 날짜와 할 일 정보를 바탕으로 AI Mate 진입 초안과 칩을 만든다.
  - Upload 추출 일정 저장 시 전용 reducer action을 dispatch한다.
- `MonthPage` / `MonthScheduleDialog`
  - Upload 추출 일정에도 편집 폼을 열고 저장 대상 ID를 전달한다.
- `ScheduleEditorDialog`
  - Upload 이동 링크와 읽기 전용 분기를 제거하고 모든 지원 일정에 저장 버튼을 제공한다.

## 7. 오류 및 접근성

- 일정 제목 누락과 종료 시간이 시작 시간보다 빠른 경우 기존 인라인 오류를 유지한다.
- 할 일 카드 본문은 키보드로 접근 가능한 버튼 영역으로 제공하고 완료 체크박스와 클릭 동작을 분리한다.
- Prompt Chips는 의미가 드러나는 버튼 이름을 제공한다.
- 패널을 열 때 자동 전송하지 않으며, 사용자가 입력창 내용을 검토·수정할 수 있다.

## 8. 테스트 및 완료 기준

- 온보딩 아이콘 이미지가 프레임 안에 있고 연결선 레이어가 이미지보다 뒤에 있는지 컴포넌트 구조와 스타일로 검증한다.
- 계획 미생성 버튼이 AI Mate를 열고 정확한 draft만 채우는지 검증한다.
- 할 일 카드 선택 시 세 Prompt Chips가 표시되고 각 칩이 할 일·날짜 맥락을 반영한 draft를 만드는지 검증한다.
- 빈 날짜의 `계획 조정` 버튼이 날짜 기반 draft를 만들고 메시지를 보내지 않는지 검증한다.
- AI Mate 대화에 `time` 요소가 렌더링되지 않는지 검증한다.
- Today와 Month에서 Upload 추출 일정을 수정·저장할 수 있고 양쪽 화면이 갱신된 값을 읽는지 검증한다.
- Today와 Month의 일정 추가 버튼이 `추가`로 표시되는지 검증한다.
- 전체 Vitest, TypeScript 검사, Vite 프로덕션 빌드를 통과한다.
- 모바일 뷰포트에서 온보딩, Today, Month, AI Mate 핵심 상태를 캡처해 P0~P2 시각 결함이 없는지 확인한다.
