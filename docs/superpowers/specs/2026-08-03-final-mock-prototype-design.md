# CatchUp 최종 목 프로토타입 디자인 명세

## 1. 목적

실제 기능 연결 전 마지막 목 프로토타입의 화면과 상호작용을 확정한다. 기존 CatchUp의 보라색 브랜드 톤과 모바일 우선 구조는 유지하면서 Google Calendar 온보딩, Today, AI Mate, Month 화면을 사용자 피드백에 맞게 정리한다.

이번 변경은 목 데이터와 로컬 상태로 동작하는 프로토타입에 한정한다. 실제 Google OAuth, 외부 캘린더 동기화, AI API, 서버 저장은 구현하지 않는다.

## 2. 범위와 원칙

- `PRD.md`를 기준 문서로 삼고 `README.md`, `IA.md`, `USER_FLOW.md`, `SCREEN_SPEC.md`를 함께 갱신한다.
- 관련 화면 디자인 문서인 `ONBOARDING_DESIGN.md`, `TODAY_DESIGN.md`, `AIMATE_DESIGN.md`, `MONTH_DESIGN.md`도 최종 동작과 일치시킨다.
- `DATA_MODEL.md`와 `API_SPEC.md`는 수정하지 않는다.
- AI가 생성한 할 일의 내용, 날짜, 시간, 우선순위는 화면에서 직접 편집하지 않는다. 생성·수정·추가는 AI Mate 대화로만 처리한다.
- 캘린더 일정은 사용자가 직접 추가·수정할 수 있다. 이는 AI가 생성한 할 일과 구분한다.
- 주간 계획은 사용자가 설정한 요일과 시간에 주 1회만 생성하며, AI Mate 계획 조정은 하루 최대 10회로 유지한다.
- 모든 예시에는 익명화된 가짜 학생 데이터와 샘플 일정만 사용한다.

## 3. 선택한 설계 접근

Month 색상은 개별 일정 속성이 아니라 과목 또는 개인 일정 카테고리의 공통 속성으로 취급한다.

- 학업 일정에서 색상을 바꾸면 같은 과목의 모든 일정에 함께 적용한다.
- Google Calendar와 CatchUp에서 직접 추가한 개인 일정은 하나의 개인 일정 카테고리 색상을 공유한다.
- 별도 색상 설정 화면은 만들지 않는다. 날짜 선택 후 일정 수정 화면에서 6색 팔레트를 제공한다.
- 개별 일정만 다른 색상을 사용하는 예외 기능은 제공하지 않는다.
- 과목과 개인 일정 카테고리가 6개를 넘으면 팔레트를 순환해 재사용한다. 사용자는 이후 카테고리 단위로 색상을 바꿀 수 있다.

이 방식은 화면과 상태 구조를 최소화하면서 캘린더에서 같은 과목을 일관되게 인식하게 한다.

## 4. Google Calendar 연동 온보딩

### 화면 변경

- 제목 `Google Calendar 연결`은 유지한다.
- 제목 아래의 `개인 일정과 수업 시간을 함께 반영해요` 설명은 삭제한다.
- 기존 CSS로 그린 다색 Google Calendar 아이콘을 사용자가 제공한 파란색 `31` 아이콘 이미지로 교체한다.
- CatchUp 아이콘, 점선 연결 그래픽, 혜택 목록, 연결 버튼, 나중에 하기 버튼은 유지한다.

### 상태와 상호작용

- 연결 전, 연결 중, 연결 실패, 연결 완료 목 상태를 유지한다.
- 연결 완료 시 Today로 이동하고, 실패 시 같은 화면에서 다시 시도할 수 있다.
- 이미지에는 의미를 중복 전달하지 않도록 장식 이미지로 처리하고 연결 섹션 전체에 접근 가능한 이름을 유지한다.

## 5. Today 화면

### 상단과 날짜 선택

- `오늘도 따라잡아볼까요?` 상단 인사 문구와 해당 헤더 여백을 삭제한다.
- 이번 주 월요일부터 일요일까지의 날짜 스트립을 화면 최상단 핵심 요소로 둔다.
- 선택 날짜 원은 `#8C6EF6` 배경과 흰색 숫자로 표시한다.
- 오늘이지만 선택되지 않은 날짜는 보라색 테두리로 구분한다.

### AI Mate 브리핑 카드

계획이 있을 때 문구를 다음 두 줄로 고정한다.

1. `4주 일정을 고려해 중요한 일부터 정리했어요.`
2. `우리 오늘도 같이 하나씩 따라잡아봐요!`

카드 안의 조정 잔여 횟수와 장황한 동기부여 문구는 제거한다. AI Mate 라벨과 캐치 캐릭터는 유지한다.

### 할 일 섹션

- 섹션 제목 옆 개수를 제거한다.
- 추가 버튼, 개별 수정 버튼, `추천 이유 보기` 버튼을 제거한다.
- 각 카드에는 완료 체크, 과목명, 할 일 제목, 예상 소요시간, 필요한 경우 마감일만 표시한다.
- 우선순위 라벨은 제거한다.
- 예상 소요시간은 `1H`, `2.5H`, `30M`처럼 간결하게 표시한다.
- 계획 수정·추가와 추천 이유 질문은 AI Mate에서만 수행한다.
- 빈 상태에서도 Today 본문에 계획 생성 버튼을 두지 않고 AI Mate를 이용하라는 짧은 안내만 표시한다.

### 일정 섹션

- 섹션 제목 옆 개수를 제거한다.
- `일정 추가` 버튼을 제공한다. 누르면 선택 날짜가 미리 채워진 일정 입력 창을 연다.
- 기존 일정 카드는 전체를 선택 가능한 요소로 만든다. 카드를 누르면 해당 일정이 채워진 수정 창을 연다.
- 별도의 연필 아이콘이나 수정 버튼은 두지 않는다.
- Google Calendar 또는 CatchUp 일정의 입력·수정 창에는 제목, 날짜, 시작·종료 시간, 유형을 제공한다.
- 업로드 자료에서 추출된 학업 일정은 제목·날짜 등의 직접 수정 대상이 아니므로 상세값을 읽기 전용으로 보여주고 `Upload에서 수정` 안내를 제공한다.
- 색상은 Month와 같은 6색 팔레트를 사용한다. 카테고리 변경 규칙도 동일하다.

## 6. AI Mate 화면

### 첫 진입 안내

사용자가 처음 AI Mate를 열었을 때 입력 전부터 캐치의 메시지 두 개를 순서대로 표시한다.

1. `안녕하세요! 여러분의 AI Mate 캐치예요.`
2. `이번 주 계획을 요청할 때 원하는 공부 방식이나 개인 요구사항도 함께 알려주세요. 계획에 반영해드릴게요.`

이 안내는 빈 상태 문구가 아니라 실제 assistant 메시지 버블로 표시해 이후 대화 흐름과 자연스럽게 이어지게 한다.

### 계획 생성 완료 안내

계획 생성 성공 응답에는 다음 내용을 포함한다.

- 이번 주 계획 생성 완료
- 사용자의 개인 요구사항을 반영했다는 요약
- 계획의 수정 또는 할 일 추가를 AI Mate에 요청할 수 있다는 안내
- 특정 할 일의 추천 이유도 질문할 수 있다는 안내

예시 응답:

`이번 주 계획을 만들었어요. 요청한 공부 방식도 함께 반영했어요. 바꾸거나 추가하고 싶은 할 일이 있으면 말씀해주세요. 각 할 일을 추천한 이유도 물어볼 수 있어요.`

### 제한과 기존 동작

- 주간 계획 생성 주 1회 제한과 같은 주 재생성 차단을 유지한다.
- 계획 수정·추가 요청만 하루 10회 조정 사용량에 포함한다.
- 추천 이유 질문과 도움말은 조정 횟수를 차감하지 않는다.
- 연결 전, 업로드 전, 확인 필요, 생성 가능 시간 전 상태 안내를 유지한다.

## 7. Month 화면

### 캘린더 표시

- 날짜 아래 점 표시를 제거한다.
- 일정 제목을 날짜 칸 안의 작은 색상 칩으로 직접 표시한다.
- 칩에는 가능한 범위에서 일정 제목을 한 줄로 표시하고 넘치는 텍스트는 말줄임한다.
- 한 날짜의 일정이 표시 가능 개수를 넘으면 나머지는 `+N`으로 표시한다.
- 다른 달 날짜의 일정은 낮은 불투명도로 표현한다.
- 칩을 포함한 날짜 칸 전체를 선택하면 해당 날짜의 일정 상세 창을 연다.

### 제한 팔레트

사용 가능한 색상은 아래 6개로 제한한다.

- `#C7B9FA`
- `#E9E0FF`
- `#F8B1FB`
- `#FEE8FF`
- `#A5D1FF`
- `#D9F0FF`

밝은 색상 위에는 읽기 쉬운 어두운 텍스트를 사용한다. 색상만으로 일정을 구분하지 않고 일정 제목을 항상 함께 표시한다.

### 기본 색상 배정

- 같은 `courseName`의 학업 일정은 같은 기본 색상을 사용한다.
- Google Calendar와 CatchUp 개인 일정은 하나의 개인 일정 기본 색상을 공유한다.
- 과목은 처음 등장한 순서대로 사용 가능한 팔레트에 안정적으로 배정한다.
- 6개를 넘는 카테고리는 팔레트를 순환해 재사용한다.

### 일정 상세·수정 창

- 날짜를 선택하면 해당 날짜의 일정 목록과 `일정 추가` 동작을 표시한다.
- 일정 목록에는 별도 수정 아이콘을 두지 않는다. 일정 행을 누르면 수정 폼으로 전환한다.
- Google Calendar 또는 CatchUp 일정은 제목, 날짜, 시간, 유형과 색상을 수정할 수 있다.
- 업로드 자료에서 추출된 학업 일정은 제목, 날짜, 시간은 읽기 전용으로 표시하고 과목 공통 색상만 변경할 수 있다. 내용 변경은 Upload 화면으로 안내한다.
- 모든 일정 상세에는 6색 팔레트를 표시한다.
- 학업 일정의 색상 아래에는 `같은 과목의 모든 일정에 적용돼요.`를 표시한다.
- 개인 일정의 색상 아래에는 `모든 개인 일정에 적용돼요.`를 표시한다.
- 색상 저장 시 Month에서 해당 카테고리의 일정 칩이 모두 함께 갱신된다.

## 8. 상태 구조와 컴포넌트 경계

목 프로토타입에는 다음 범위의 상태만 추가한다.

- `categoryColorByKey`: `course:<과목명>` 또는 `personal` 키와 6색 값의 대응
- 일정 입력·수정 창에서 사용할 선택 일정과 임시 입력값
- AI Mate 초기 안내 메시지

일정 입력 폼은 Today와 Month가 같은 동작을 공유하도록 재사용 가능한 컴포넌트로 분리한다. Month 캘린더의 색상 결정은 일정 자체에 색상을 복제하지 않고 카테고리 키를 통해 조회한다.

실제 서버 저장, Google Calendar 원본 쓰기, 데이터베이스 마이그레이션은 이번 프로토타입에 포함하지 않는다. 목 프로토타입에서는 Google Calendar 일정 수정 결과를 로컬 상태로만 보여준다.

## 9. 오류·빈 상태·접근성

- 일정 제목이 비어 있거나 종료 시간이 시작 시간보다 빠르면 저장하지 않고 오류 문구를 표시한다.
- 일정이 없는 날짜에는 빈 상태와 `일정 추가` 동작을 제공한다.
- 선택 날짜, 선택 색상, 일정 카드에는 키보드 포커스와 접근 가능한 이름을 제공한다.
- 색상 선택은 색상 견본뿐 아니라 `색상 1`부터 `색상 6`까지의 접근 가능한 라벨과 선택 상태를 제공한다.
- Month 일정 제목 칩은 배경색과 무관하게 텍스트 대비를 확보한다.
- 모바일에서 Month 제목 칩이 날짜 숫자나 인접 칸을 침범하지 않도록 행 높이와 말줄임을 검증한다.

## 10. 문서 변경 범위

- `PRD.md`: Month 카테고리 색상과 일정 제목 표시를 MVP에 포함하고 기존 제외 문구를 제거한다.
- `README.md`: 1차 MVP 범위와 현재 문서 목록을 최신화한다.
- `IA.md`: Today 직접 일정 추가·수정, Month 제목 칩과 과목별 색상, AI Mate 선제 안내를 반영한다.
- `USER_FLOW.md`: 일정 카드 선택 수정, 일정 추가, 과목 전체 색상 변경, AI Mate 초기·완료 안내 흐름을 반영한다.
- `SCREEN_SPEC.md`: 화면별 표시 문구, 버튼 유무, 색상 값, 편집 동작을 상세히 반영한다.
- 화면 디자인 문서: 온보딩, Today, AI Mate, Month의 최종 시각·상호작용을 반영한다.
- `DATA_MODEL.md`, `API_SPEC.md`: 변경하지 않는다.

## 11. 검증 기준

### 자동 검증

- 기존 테스트를 모두 통과한다.
- 변경된 문구와 버튼 제거·추가 동작을 컴포넌트 테스트로 검증한다.
- Today 선택 날짜가 `selected` 상태를 유지하고 일정 추가·수정 창이 올바른 날짜와 값을 받는지 검증한다.
- AI Mate 첫 진입 안내와 계획 생성 완료 후 후속 안내를 검증한다.
- Month에서 점이 사라지고 제목 칩과 `+N`이 표시되는지 검증한다.
- 한 과목의 색상 변경이 같은 과목의 모든 Month 일정에 적용되는지 검증한다.
- 개인 일정 색상 변경이 Google Calendar와 CatchUp 개인 일정에 함께 적용되는지 검증한다.
- `pnpm test`, `pnpm typecheck`, `pnpm build`를 실행한다.

### 시각 검증

- 모바일과 데스크톱 크기에서 온보딩, Today, AI Mate, Month를 직접 확인한다.
- 첨부된 Google Calendar 아이콘, `#8C6EF6` 선택 날짜, 6색 팔레트가 기준 이미지와 일치하는지 확인한다.
- Month 일정 제목이 한눈에 보이고 과도한 일정은 `+N`으로 정리되는지 확인한다.
- 일정 추가·수정과 색상 변경을 실제 클릭 흐름으로 확인한다.

## 12. 완료 조건

- 요청된 네 화면의 문구, 버튼, 아이콘, 색상과 상호작용이 목 프로토타입에 반영된다.
- 관련 문서가 동일한 기능 범위와 용어를 사용한다.
- `DATA_MODEL.md`와 `API_SPEC.md`에는 변경이 생기지 않는다.
- 자동 검증과 핵심 화면 시각 검증이 통과한다.
